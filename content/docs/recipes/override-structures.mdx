---
title: Override a Built-in Structure
description: Replace a default class with your own subclass and keep everything strongly typed.
---

Hoshimi builds every core object through a `Structures` factory. Swap an entry for your own subclass to add methods or state, and augment `CustomizableStructures` so the types follow.

## The override pattern

```ts twoslash copy wrap title="custom-player.ts"
import { Player, Structures } from 'hoshimi';

class CustomPlayer extends Player {
  public isDJModeEnabled(): boolean {
    return this.volume > 120;
  }
}

Structures.Player = (...args) => new CustomPlayer(...args);

declare module 'hoshimi' {
  interface CustomizableStructures {
    Player: CustomPlayer;
  }
}
```

<Callout type="warn" title="The augmentation is what re-types everything">
  Assigning to `Structures` swaps the class at runtime; augmenting `CustomizableStructures` is what makes
  `player.filterManager`, `PlayerStructure` and every other reference resolve to your subclass. A local
  `interface CustomizableStructures` in your file does nothing — it has to be inside
  `declare module 'hoshimi'`.
</Callout>

## Override several at once

```ts twoslash copy wrap title="multi-override.ts"
import { LyricsManager, Node, Player, Structures } from 'hoshimi';

class ExtendedPlayer extends Player {}
class ExtendedNode extends Node {}
class ExtendedLyricsManager extends LyricsManager {}

Structures.Player = (...args) => new ExtendedPlayer(...args);
Structures.Node = (...args) => new ExtendedNode(...args);
Structures.LyricsManager = (...args) => new ExtendedLyricsManager(...args);

declare module 'hoshimi' {
  interface CustomizableStructures {
    Player: ExtendedPlayer;
    Node: ExtendedNode;
    LyricsManager: ExtendedLyricsManager;
  }
}
```

Every structure is overridable: `Player`, `Node`, `NodeManager`, `Rest`, `Queue`, `LyricsManager`, `FilterManager`, `Track`, `UnresolvedTrack`, `PlayerVoiceState` and `PlayerStorageAdapter`.

## Use the structure types

The `*Structure` type aliases resolve to the final instance type — default or your override — so use them in signatures instead of the concrete class.

```ts twoslash copy wrap title="structure-types.ts"
import type { PlayerStructure, TrackStructure } from 'hoshimi';

function attachFeatures(player: PlayerStructure): void {
  // Works with the default Player or any custom replacement.
  console.log(`Guild: ${player.guildId}`);
}

function inspectTrack(track: TrackStructure): string {
  return track.info.title;
}
```

## Best practices

- Override structures **once during bootstrap**, before creating any managers.
- Keep constructor signatures unchanged to stay compatible with the factory.
- Add narrow, domain-specific methods instead of rewriting core flow logic.
- Use `*Structure` types in signatures to avoid coupling to concrete classes.

<Callout type="info" title="Typing data, not classes">
  To type the `requester`/`userData` on tracks or the keys of `player.data` you do not need a subclass —
  see [Type your track requester](/docs/recipes/typed-requester) and
  [Type player.data keys](/docs/recipes/typed-player-data).
</Callout>
